# AGENTS.md — meshview

Instructions, status and invariants for coding agents working on this repository.
Read this file before changing anything; the rules here exist because breaking
them produced wrong scientific conclusions or a non-compliant release once already.

## What this is

`meshview` is a **headless, CPU-only rasterizer for comparing triangle meshes
side by side**. It loads Wavefront OBJ files and renders each under one
identical orthographic camera into a labelled contact-sheet PNG. No GPU, no
window system, no interactivity, no scene graph.

It exists to debug solvent-excluded-surface (SES) meshes generated by
[molses](https://github.com/uvar-apps/molses): the whole point is that the
same world-space region of several meshes appears at the same scale and
orientation, so **a pixel difference means a geometry difference and nothing
else**. It reads any OBJ. It is the Rust port of a Python tool; the port's
reason for existing is speed with identical behavior.

Primary consumers: the `meshview` CLI, and the `molses` dev flow calling the
library API (`load_obj`, `render`, `render_compare`) directly. Keep that API
usable; breaking it forces a semver bump and coordination.

## Architecture

```
meshview (lib + bin)
├── obj.rs       load_obj / load_obj_from_str → Mesh { positions, normals, indices }
│                4 corner forms, vn-index binding (first wins), geometric fallback
├── camera.rs    orthographic Camera (focus, zoom, yaw·pitch·roll → M = Rz·Ry·Rx)
│                project_point; project_mesh → (sx, sy, depth, nview)
├── shading.rs   view-space two-sided Lambert; DEFAULT_LIGHT (0.35,0.45,0.82),
│                DEFAULT_AMBIENT 0.30
├── raster.rs    render() → Raster { surface gray layer + coverage mask }
│                strict z-buffer, per-row span solve, colorize(bg, alpha) step
├── sheet.rs     render_compare() → RgbaImage sheet + per-tile masks
│                supersample (render at size*aa, Lanczos3 down), layout,
│                deterministic PNG writers (write_png_rgba / write_png_gray)
├── font.rs      built-in 5×7 ASCII bitmap atlas (no system fonts, deterministic)
└── main.rs      clap CLI (--zoom/--focus/--size/--aa/--per-row/--label/
                 --yaw/--pitch/--ambient/--bg/--bg-opacity/--mask)
```

Data flow: `load_obj → Mesh → (one shared) Camera → render → Raster
(surface+mask) → colorize(bg, alpha) → supersample-downscale → sheet layout →
labels → deterministic PNG`. Note the raster is **colour-free by design**: it
produces a surface layer plus the coverage mask; background colour/opacity are
compositing choices applied later, at supersample resolution so edges (and
alpha) antialias with the geometry.

## The four honesty rules (never regress these)

Each exists because the violation produced a wrong scientific conclusion once.
A change that breaks any of them is broken even if screenshots look fine.
They are enforced by tests (`tests/selftest.rs`, `tests/rendering.rs`).

1. **Never back-face cull geometrically; visibility is the z-buffer only.**
   A geometric orientation test disagrees with the stored smooth normals of a
   creased surface (historical failure: checkerboard of background speckles on
   *every* mesh, including the reference — blamed on the meshes for a while).
   Orientation belongs exclusively to shading: turn the interpolated normal
   toward the camera before lighting (two-sided Lambert), so inverted normals
   read dark instead of punching holes. Enforced by: "no enclosed uncovered
   pixel" and "flipped normals cover identically".
2. **Normals bind by the face-corner's `vn` index, never by arrival order.**
   In `a/b/c`, `b` is a texture coordinate — never interpret it as a normal.
   Bind each `vn` to the position referencing it (flat-shaded exports index
   `vn` differently from `v`). Vertices left unbound get area-weighted
   geometric normals; everything is re-normalized (exported normals are not
   always unit). Enforced by: `vn_binds_by_index_not_arrival_order`,
   `vt_corners_fall_back_to_geometric_normals`, sample loader tests.
3. **Coverage is an explicit boolean mask returned by the renderer, never
   inferred from pixel values.** A lit surface pixel can read exactly the
   background byte (a colour-based hole-check "found" 3,208 holes on a
   flawless sphere). All hole/speckle measurement goes through `Raster::is_covered`,
   never through gray levels. Enforced by: `covered_pixel_can_equal_background_byte`.
4. **One camera for the whole sheet.** `focus` + `zoom` shared by every mesh
   in a compare run; default focus = first mesh's centroid. Never auto-fit
   per-mesh bounding boxes — varying magnification between panels is how a
   comparison starts lying. Enforced by: `shared_camera_does_not_auto_fit`.

## Exact semantics to preserve (parity contract)

These match the Python original (`/Users/ugo/projects/SES/tools/meshview/`,
read-only — see Working rules). Deviating from any of them changes output;
deviate only with a decision, a test, README documentation, and a semver bump.

**Loader**
* Lines starting exactly `v `, `vn `, `f ` only; everything else ignored
  gracefully. `v`/`vn` lines may carry extra trailing floats (vertex colors) —
  first three only.
* Fan triangulation: corners `(0,k,k+1)` for `k in 1..n-1`; faces with <3
  corners produce nothing.
* Corner forms: `v`, `v/vt`, `v//vn`, `v/vt/vn`. Normal present iff parts[2]
  exists and is non-empty.
* vn binding: first reference wins; out-of-range or negative `vn` indices are
  silently unbound; unbound vertices get face-order-accumulated area-weighted
  geometric normals (deterministic float sum), then all normals are divided by
  `max(len, 1e-12)` (zero-length vectors stay exactly zero — matches Python;
  the dragon has genuine zero-area vertices).
* Errors: no vertices → error; negative/zero face position index → error
  (Python silently wrapped these — a ported bug class, do not reintroduce);
  out-of-range face index → error; malformed numeric field → error **with the
  line number**.

**Camera** (orthographic, looking down −z)
* `M = Rz(roll)·Ry(yaw)·Rx(pitch)`; `p' = M·p`; `f = M·focus`;
  `x = (p'.x−f.x)·zoom + size/2`; `y = −(p'.y−f.y)·zoom + size/2`;
  `depth = p'.z`, **larger depth = nearer**.
* Shading uses view-space normals `M·n`: the light is defined relative to the
  camera. That is what makes different-geometry panels comparable.

**Rasterizer**
* Grayscale surface in float64 math; pixel value `(255·shade)` truncated to
  u8. Surface buffer holds shaded pixels only; uncovered reads 0 and is
  meaningless without the mask.
* Window reject on face bbox (max ≥ 0, min < size in x and y); faces sorted
  stable by mean depth ascending via `total_cmp` (far→near on a strict z
  buffer: a pixel is replaced only by `z > zbuf`; exact ties resolve by face
  order — deterministic).
* `|den| < 1e-9` → skipped as degenerate. Barycentric hit tolerance `w ≥ −1e-7`
  (exact per-pixel test; the per-row span solve is conservative padding on
  top and must never become the sole arbiter).
* Two-sided Lambert: normalize interpolated normal (guard 1e-12), `sgn =
  nz < 0 ? −1 : +1`, `shade = ambient + (1−ambient)·max(0, n·l·sgn)`.
* Deliberate deviation from Python: no single-pixel flat-shade fast path
  (Python shaded such faces with the *un-normalized* corner average — worse,
  and the only source of the tiny cross-check MAD tail).

**Sheet / output**
* Supersample: render at `size·aa`, Lanczos3 down to `size`. **Consequence:
  on-screen magnification is `zoom/aa` px per world unit** (the `+size/2`
  centering makes zoom resolution-independent, then the downscale halves it).
  The Python original behaves identically and all documented framing numbers
  ("protein whole at zoom 50", "crevice at zoom 110") assume it. If you
  "fix" this, every framing number changes — treat as a deliberate release.
* Layout: `cols = if per_row == 0 { n } else { per_row }`, `rows = ceil(n/cols)`, pad 12, header
  26, tile at `x = pad + c·(size+pad)`, `y = header + pad + r·(size+header)`,
  label at `(x+4, y−18)` in RGB(200,0,0), opaque, 2× scale. Labels default to
  file stems.
* `aa` is clamped `≥ 1`; label list shorter than meshes → error, surplus
  labels ignored.
* Background: `--bg` (default **black**; `black|white|gray`, gray level
  0..=255, `#rgb`/`#rrggbb`) colours the uncovered surface region and the
  sheet canvas; `--bg-opacity` (0..=1) sets the alpha of every non-surface
  pixel. Surface is always opaque. Colourize **before** the aa downscale.
  Sheets are RGBA PNGs; still byte-deterministic.
* **Determinism**: identical inputs + options ⇒ byte-identical PNG. Fixed PNG
  encoder settings (`CompressionType::Default`, `FilterType::Adaptive`), no
  metadata/time chunks, no HashMap iteration affecting output, no ambient
  state. Verified across processes in `tests/cli.rs`. Never reintroduce
  source of nondeterminism; if you parallelize (rayon), per-row-strips of the
  sequential algorithm are the only pre-approved shape (pixel sets are
  disjoint, per-pixel face order preserved ⇒ bitwise identical), and the
  byte-equality tests must still pass under it.

**CLI**: prints `wrote <path>` per output file; error → `meshview: <msg>` on
stderr, exit 1. Defaults: zoom 100, size 620, aa 2, ambient 0.30, per-row 0,
yaw/pitch 0, bg black, bg-opacity 1.

## Testing policy

* **Properties, not golden images.** Golden images bake in bugs; property
  tests bake in truths. Keep assertions as tolerances and invariants (areas,
  std/gradient bounds, byte equality between two runs, mask flood-fill hole
  checks), except the intentional determinism tests that *are* byte equality.
* Full `selftest.py` port is 1:1 — keep all 13; if the Python original gains
  a check, port it.
* Cross-check recipe (against Python): `python3` here has numpy+PIL; from
  `/Users/ugo/projects/SES/tools/meshview` import `render` as a module,
  build the same `Camera` (focus = first mesh centroid when unset), render at
  identical size/zoom **aa 1 both sides**, compare mask counts and the
  boundary-eroded covered-core MAD. Expect ≈ 0 except sub-pixel tails; pass
  `--bg white` on the Rust side for direct byte comparison.
* Perf proxy regeneration (the 1M-vertex budget check) — UV sphere nu=1414,
  nv=707, r=17.5 Å, `f i//i` form written to `/tmp/million_sphere.obj`
  (~1M vertices, ~2M faces, 165 MB), then time
  `meshview /tmp/million_sphere.obj --size 900 --aa 2 --zoom 110`. Budget 2.5 s.
